# 项目需求与实现范围

## 项目目标

构建一个可在浏览器中操作的巡检机器人二维仿真系统：访客查看二维地图、手动控制机器人，并观察位置、朝向与运行状态变化。本项目按模板仓库 `Yhimhas/patrol-sim` 的验收要求开发，技术方案为 Python FastAPI + 原生网页。

## 完成版本

- **基础版**：全部完成。
- **标准版专项**：路径规划、虚拟传感器、简单异常处理、自动巡检均已实现。
- **进阶版（规则 / 算法类）**：已实现巡检返航、运行统计、地图编辑、动态障碍与受阻自动重规划；未做额外 AI 模型或 Agent 拓展。

## 功能清单与验收对照

### 基础版

| 需求 | 实现情况 | 验收方式 |
| --- | --- | --- |
| Web 界面与二维地图 | 12×10 网格，区分空地、障碍物、检查点、机器人与规划路径 | 打开页面可见地图、边界与障碍物 |
| 后端 API | 状态、移动、规划、传感器、巡检、复位接口 | 按接口说明请求可获取地图/状态并发送指令 |
| 手动控制 | 按钮与键盘四方向移动，每次一格 | 指令发出后机器人按方向移动 |
| 边界与障碍校验 | 后端统一校验，越界/撞墙拒绝且位置不变 | 贴边移动或撞墙时机器人保持原位，页面提示原因 |
| 状态反馈 | 页面显示坐标、朝向、运行状态，与 API 返回一致 | 操作后核对页面与 `/api/state` 响应 |
| Git 版本管理 | 仓库含提交记录 | 可查看源码与提交历史 |
| 基础 CI | GitHub Actions 运行 pytest 与编译检查 | Actions 页面可见检查结果 |
| Docker 部署 | 单容器提供页面与 API | 按文档构建容器后可打开页面并完成一次手动控制 |

### 标准版专项

| 专项 | 实现情况 | 验收方式 |
| --- | --- | --- |
| 路径规划 | A* 四邻域栅格规划，绕开障碍物 | 给定起点与目标点返回可通行路径；不可达返回原因 |
| 虚拟传感器 | 沿朝向扫描前方，返回是否受阻、阻挡来源与距离 | 改变位置/朝向后读数随之变化 |
| 简单异常处理 | 不可达、移动受阻时显示中文原因并停止相关操作，状态仍可查看 | 构造受阻/不可达场景，页面有提示且机器人状态可读 |
| 自动巡检 | 启动后按检查点顺序沿规划路径依次到达，显示进度与完成状态 | 巡检完成后标记全部检查点已到达 |

### 进阶版（规则 / 算法类）

| 拓展项 | 实现情况 | 验收方式 |
| --- | --- | --- |
| 巡检返航 | 走完检查点后自动规划返回起点，到达起点才判定完成；也可手动返航 | 巡检结束后机器人回到起点，状态置为完成 |
| 运行统计 | 累计步数、路径长度、耗时与覆盖率，随状态实时返回 | 面板与 `/api/state` 的 `stats` 字段一致变化 |
| 地图编辑 | 编辑模式下点击格子增删障碍，起点、检查点与机器人所在格受保护 | 切换障碍后路径相应重算，非法格拒绝修改 |
| 动态障碍 | 可后台开关的障碍随机扰动；路径被截断时丢弃旧路径并自动重规划 | 开启后障碍位置变化，受阻后机器人重新规划继续行进 |

## 演示数据与状态规则

- 地图 12×10，左上角 `(0,0)`，`x` 向右递增，`y` 向下递增。
- 机器人初始位置 `(0,0)`，默认朝右；障碍物不覆盖起点，全部检查点均可由起点到达。
- 状态仅保存在内存；刷新浏览器不重置位置，服务重启后恢复初始状态。
- 状态读取与更新由锁保护，避免并发请求产生竞争或非法位置。
